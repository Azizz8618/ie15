# Электроника 15ИЭ-00-013 — эмулятор терминала

Эмулятор видео-терминала **«Электроника 15ИЭ-00-013»** (Фрязинский дисплей, 1980-е)
на Python. Построен на **настоящих дампах ПЗУ** реального устройства:
знакогенератора КР556РТ5 (`rom/chargen-15ie.bin`) и клавиатуры 15ВВВ-97-006
(`rom/15bbb.rt5`).

Терминал подключается к эмулятору **БЭСМ-6** (SIMH, `~/Yandex.Disk/simh`)
и работает с готовой конфигурацией ОС **Диспак** — `BESM6/OSZAGR/dispak.ini`
(файл и номер telnet-канала не изменяются: эмулятор подстраивается под
имеющийся порт, указанный в `attach ttyN <порт>`).

## Обзор

| Параметр | Значение |
|---|---|
| Экран | 80 знаков в ряду, кадр ЭВМ 25 рядов (как Видеотон-340) и дотягивается до низа окна терминала; служебная панель — под кадром |
| Знакогенератор | 256 глифов 7×8 точек, ПЗУ КР556РТ5 (реальный дамп) |
| Клавиатура | 15ВВВ-97-006 (ёмкостная матрица + ПЗУ `15bbb.rt5`) |
| Кодировка | КОИ7 (ГОСТ 27463-87), 7 разрядов; НАБОРЫ Н0 (ASCII) / Н1 (русские верх+низ) / Н2 (VT-52) — F8, `--nabor` |
| Команды | режим 2 — «набор команд №2» (VT52) по умолчанию; режим 1 — только УП |
| Линия | токовая петля 20 мА → поверх TCP (telnet SIMH) или SSH |
| Режимы | АВТОНОМНО (локальный буфер, отмена правок Ctrl+U по слову, сообщения ЭВМ — индикатор «ОТ ЭВМ») / С ЭВМ (обмен с линией) |
| Клавиши | ОТМЕНА (Ctrl+U); УДЕРЖАНИЕ (Ctrl+L); К ВЫДАЧЕ (Ctrl+Q); СПРАВКА (F12); УПР.СИМВ (F7); НАБОР (F8) — Н0 (ASCII) → Н1 (русские верх+низ) → Н2 (VT-52, по умолчанию); СЕТЬ (F9); ПЕРЕДАЧА (F10) |
| Терминал | обычный (юникод) или «жёсткий» без юникодного шрифта — кириллица уходит латиницей, псевдографика ASCII (см. «Жёсткий терминал») |

## Возможности

- Рендер экрана по реальным глифам ПЗУ: ANSI (зелёный люминофор) и PNG.
- Кадр ЭВМ **дотягивается до низа окна**: подвал занимает минимум рядов,
  остальное место окна отдано кадру (у настоящего 15ИЭ — 25 рядов, кадр
  выше только потому, что окно терминала выше). Пустоты под подвалом не
  остаётся ни при каком масштабе шрифта.
- **Подвал прижат к низу окна и не уезжает при листании истории**: PgUp,
  PgDn и колесо двигают только текст выдачи (историю + кадр), подвал с
  чертой остаётся на месте. Если окно ниже подвала, ряды подвала
  урезаются (показываются верхние — состояния), но не ценой последних
  рядов вывода: тексту остаётся не меньше трёх рядов.
- **Окно само следует за выдачей ЭВМ** — курсор всегда в поле зрения.
  Долистали историю вниз (PgDn) — окно снова следящее; раньше оно
  «отставало» от текста на строку, и следующая строка выдачи уводила
  курсор под нижнюю кромку: опускать экран приходилось вручную.
  **Ctrl+Q** — вернуть окно к живой выдаче из любого места.
- **Удержание экрана (Ctrl+L)** — выдача ЭВМ останавливается: эмулятор
  перестаёт читать линию, выдача копится в буфере сокета, машина упирается
  в него (защита от зациклившихся программ, «заливающих» экран), а экран
  замирает — можно спокойно читать. В линию уходит команда 15ИЭ «Сброс»
  (0x0C): на линии, объявленной ОС терминалом «Э» (`НУС <N> 1`), ДИСПАК
  по ней **отменяет идущую выдачу** (ОТМЕНА ВЫДАЧИ, признак BREAK).
  Повторное нажатие или Ctrl+Q — снять удержание и вернуться к выдаче.
- **Строка состояния линии над кадром** (вне кадра ЭВМ — в листание не
  попадает): `ЭВМ=6 | ТЕРМ=3 | КАНАЛ=4203 | РЕЖИМ=RAW | 11.10.2026
  02:03:04`. Номер терминала — из баннера SIMH, канал — из порта, номер
  ЭВМ — из `[line] machine`, режим линии — тоже из баннера. Состояния
  линии здесь нет: тип канала (КВУ/ДКС) и «нет связи» показывает подвал,
  ячейка `ЛИНИЯ=` (см. ниже). Баннер (`CONNECTED TO …`, `ENCODING IS …`,
  `WRU …`, дата/время) в кадр не печатается; если сообщение о подключении
  не пришло — горит красное «ПРОВЕРЬ ЛИНИЮ!». Под ней — черта «-» и одна
  пустая строка: кадр ЭВМ начинается с четвёртого ряда окна.
- Подвал (состояния + легенда клавиш) **растянут на всю ширину окна**
  (не уже 80) ячейками в **ровных колонках**: разделители « | » стоят на
  одних позициях во всех рядах, ячейки не рвутся, ряд состояний отбит
  от легенды чертой «-». Группы справки (F-клавиши, прочая клавиатура,
  сочетания с Ctrl, правка) отличает цвет; группа, целиком влезающая в
  остаток ряда, дописывается в него — свободных колонок подвал не
  оставляет (на 150 знаках — 5 рядов, на 100 — 7, на 80 — 10).
- Цвета подвала: значения состояния — `ВКЛ` зелёный, `ВЫКЛ` красный,
  остальные значения светло-голубые; `АВТОНОМНО` — красным и подчёркнутым
  (набор идёт в буфер терминала, а не в ЭВМ — потерять легко);
  F-клавиши F5…F10 (верхний ряд справки, по порядку) — жёлтые, сочетания
  с Ctrl — маджента, правка (`ДОМ`, `СТЕРСТР`, `ИНВЕРС`, `НОРМ`) — синяя.
- `--show-help` / `--no-help` (`[terminal] help = on/off`) — показать или
  убрать ряды-справку (легенду клавиш) подвала; **по умолчанию справка
  скрыта**, нижняя строка состояния (поля сеанса, `ПОСЛ:`) остаётся в любом
  случае, освободившиеся ряды достаются кадру ЭВМ. **В ходе сеанса**
  справка переключается **F12** (скрытая — в правом углу верхней строки
  состояния горит подсказка «СПРАВКА=F12»;
  формы F1 тоже распознаются, где они доходят, но F1 в ряде окружений
  занят ОС — потому основная клавиша F12; другая клавиша задаётся в `[keys]`).
- `--fit` (`[terminal] fit = on`) — режим «правильного масштаба»: эмулятор
  подгоняет окно ровно на «строка состояния + чёрта с пустой строкой +
  25 рядов кадра + подвал» (`CSI 8 ; высота ; ширина t`), а сбитый
  масштаб шрифта возвращает сам.
- Единая клавиша **НАБОР (F8)** перебирает три режима по ГОСТ 27463-87:
  **Н0** — знаки ASCII (ISO 646 IRV: `¤` `¬` `¯` вместо `$` `^` `~`);
  **Н1** — русские верхний и нижний регистры (КОИ-7 Н1: 0x40…0x5F —
  заглавные «ЮАБЦ…Ч», 0x5F — «Ъ», 0x60…0x7E — строчные) и русская
  раскладка клавиатуры; **Н2** — набор команд №2 (VT-52) с международной
  строкой знаков без замен Н0 (латиница в обоих регистрах, «^» и «$»
  на своих местах; «№» — внутренний знак, на линию идёт позицией 2/3),
  кириллица — только заглавная, кодами ЭВМ — по умолчанию, рабочий режим
  линии БЭСМ-6. Стартовый
  режим — `nabor` в конфиге / `--nabor`, индикатор в подвале;
- Полный разбор «набора команд №2» (частично VT52): курсор, стирание,
  инверсия, позиционирование `ESC Y`, идентификация `ESC Z` и др.
  Нераспознанные управляющие коды (НУС, ЕОТ …) показываются образным
  знаком `код|0x40` с «блинком» — как dim-режим Видеотона-340.
- Два режима работы, как у настоящего терминала:
  - **АВТОНОМНО** (`--mode local`) — набор в локальный буфер с эхом на экран,
    линия свободна (эхо русских букв — заглавные: Н1 не различает регистр,
    так же показывает и ЭВМ); переход из С ЭВМ (F9) добавляет текст кадра
    в буфер — набор продолжает текст экрана, ПЕРЕДАЧА (F10) отдаёт и его,
    Ctrl+U отменяет перенос;
  - **С ЭВМ** (`--mode host`) — каждый знак немедленно уходит в линию,
    эхо приходит от ЭВМ;
  - **сообщение от ЭВМ в АВТОНОМНО не лезет в кадр** (там идёт набор,
    строка легла бы под эхо и исчезла бы при первой же правке): текст
    показывает индикатор `ОТ ЭВМ=…` в строке состояния (хвост последних
    знаков и счётчик сообщений); служебный ответ на идентификацию (`ESC Z`)
    при этом уходит в линию, ОС не считает сеанс мёртвым; счётчик снимается
    при переходе в С ЭВМ (F9);
  - клавиша **SEND** (F10) — передать накопленное (незакрытую строку
    завершает ПР ПС), очистить буфер и перейти в режим С ЭВМ.
  - **отмена правок** — клавиша **Ctrl+U** возвращает буфер набора **на
    слово назад** (шаг откала — слово, а не буква: пробел/точка/ПР и
    навигация закрывают шаг; глубина — `[terminal] undo`, по умолчанию 20
    слов/действий, `0` — выключить; то же — `--undo`). Отменяется всё,
    что меняло буфер: набор, **ВЗЯТЬ** (F4), удалённая страница (F5).
    Прежнее эхо на экране стирается, остаётся ровно то, что в буфере;
    сколько шагов ещё доступно — в строке состояния (`ОТМЕНА=Ctrl+U (7)`).
    ПЕРЕДАЧА историю отмены сбрасывает.
  - **пробел поддержки** — раз в `pulse` секунд (по умолчанию 60,
    `--pulse` / `[terminal] pulse`, `0` — выключить) в линию уходит пробел,
    чтобы программы БЭСМ-6, ждущие ввода, не считали сеанс уснувшим и не
    сбрасывали его; **только в АВТОНОМНО** — в С ЭВМ терминал и так на
    связи, а лишний пробел вклинивается в выдачу и сбивает её; пробел без
    ПР строку не заканчивает — вводом для программы не считается, а его
    эхо на экран не выводится;
  - **проверка живости линии** — раз в `check` секунд (по умолчанию 60,
    `--check` / `[terminal] check`, `0` — выключить) у линии (моста SSH)
    спрашивается состояние: связь может пропасть «молча» — соединение не
    рвётся, а данных нет, и подвал продолжает врать `ЛИНИЯ=КВУ`/`ЛИНИЯ=ДКС`;
    ответа нет — в подвале `ЛИНИЯ=НЕТ` (см. «Контроль состояния SSH-моста»);
- Клавиша **НАБОР** (F8) — переключение наборов команд, как на клавиатуре
  15ВВВ: набор 2 (№2, VT52) по умолчанию — с ним терминаль и работает на
  линии БЭСМ-6; в наборе 1 разбираются только управляющие коды.
  В служебной строке (подвале, строки 25+) — панель состояний всех
  управляющих сигналов (`СЕТЬ`, `НАБОР`, `ЛИНИЯ`, `РАСК`, `ЭХО`, `ВИДЕО`,
  `БУФЕР`, `УПР.СИМВ`) и легенда «функция=клавиша» с активаторами F7–F10;
  последняя нажатая клавиша видна в `ПОСЛ:`. Панель растянута на всю
  ширину окна (не уже 80) и занимает минимум рядов — на 80 знаках 6 рядов.
  Переключение сеанса АВТОНОМНО ↔ С ЭВМ — F9, показ знаков УП — F7
  (см. `re_dispak/re-dispak/docs/COMMANDS.md`).
- КОИ7 Н1 в обе стороны: русские буквы кодируются/декодируются по таблице
  `ЮАБЦДЕФГХИЙКЛМНОПЯРСТУЖВЬЫЗШЭЩЧ`. Внутри эмулятора заглавные несут
  «бит алфавита» (0x80), поэтому «М» не сливается с возвратом каретки;
  на линию они сворачиваются в зависимости от её кодировки (см. ниже).
- Линии: `tcp://` (прямое подключение к telnet-линии SIMH), `ssh://` (через
  `besm6/ssh_bridge.py`), `stdio://` (отладка без сети).
- **Жёсткий терминал** (см. «Жёсткий терминал» ниже): работает и там, где
  юникода нет — `LC_ALL=POSIX`, консоль без юникодного шрифта, KOI8-R/cp866.
- Кодировка линии определяется по баннеру SIMH (`Encoding is UTF-8`,
  `RAW`/`RAW8`, `KOI-7 …`, `Connected to DKS`) и подстраивается под приём
  и передачу:
  UTF-8-кириллица от ЭВМ декодируется в КОИ7, обратно русские буквы уходят
  либо как UTF-8, либо как внутренние 7-разрядные коды (строка 0x60…0x7E);
  telnet-IAC вырезается stateful в `link.py`, обрыв UTF-8 на границе `recv`
  дозаполняется из следующего чтения.

## Быстрый старт

Требуется Python 3.10+. Сторонние зависимости — только `paramiko` для SSH-линии
(для `tcp://` и `stdio://` ничего не нужно).

```bash
cd ~/Yandex.Disk/ie15

# 1. Проверка без сети (демо-скрипт + PNG)
python3 -m ie15emu --script demo --png shots/demo.png

# 2. Запуск БЭСМ-6 с готовым dispak.ini (отдельная tmux-сессия, файл не меняем)
tmux new-session -d -s besm6 -c
~/Yandex.Disk/simh/BESM6/OSZAGR/dispak.ini

# 3. Подключение терминала к telnet-линии (порт как в dispak.ini,
#    см. строку 'attach ttyN <порт>')
python3 -m ie15emu --line tcp://127.0.0.1:4202 --png shots/besm6.png

# 4. То же через SSH-мост (вторая tmux-сессия); цель можно задать
#    диапазоном — мост сам выбирает первую свободную линию Э-60
python3 besm6/ssh_bridge.py --hostkey besm6/host_ed25519_key \
        --port 2222 --target 127.0.0.1:4199-4223
python3 -m ie15emu --line ssh://ie15@127.0.0.1:2222 --password ie15

# 5. Прямой TCP с перебором диапазона (занятые линии пропускаются)
python3 -m ie15emu --line tcp://127.0.0.1:4202 --port 4202-4223
```

## Установка (ярлык на рабочем столе)

**Linux** — ярлык в меню приложений и на рабочий стол; двойной щелчок
открывает окно терминала с интерактивным сеансом (длится до Ctrl-C):

```bash
cd ~/Yandex.Disk/ie15 && ./install.sh
```

**Windows** — Python 3.10+ (для `ssh://` ещё `pip install paramiko`), затем:

```bat
powershell -ExecutionPolicy Bypass -File install.ps1
```

Ярлык «Электроника 15ИЭ (терминал)» запускает `ie15.cmd` в окне консоли.

## Конфигурация (ie15.conf)

Файл `ie15.conf` в корне проекта задаёт подключение по умолчанию
(аргументы командной строки перекрывают его):

| Секция/параметр | Назначение |
|---|---|
| `[line] type` | `ssh` (через мост) или `tcp` (telnet-линия SIMH напрямую) |
| `[line] server` | адрес сервера с БЭСМ-6 / SSH-мостом |
| `[line] port` | номер канала — telnet-порт линии SIMH (`attach ttyN <порт>`); можно список (`4202,4210`) или диапазон (`4202-4223`): берётся первая свободная линия, занятые пропускаются |
| `[line] ssh_port` | порт SSH (22 — sshd сервера; 2222 — мост `ssh_bridge.py`), тоже список/диапазон |
| `[line] machine` | номер ЭВМ для строки состояния над кадром (пусто — не показывается) |
| `[ssh] user` | пользователь SSH (по умолчанию `test@besm6.cs.msu.ru`) |
| `[ssh] keyfile` | файл закрытого ключа ssh по умолчанию (`~/.ssh/besm_test`; `~` раскрывается; если файла нет — используется пароль) |
| `[ssh] password` | пароль (когда ключ не задан/не найден) |
| `[terminal] mode` | `host` (С ЭВМ) или `local` (АВТОНОМНО) |
| `[terminal] sets` | набор команд при запуске: `2` (VT52) или `1` |
| `[terminal] history` | строк «истории» выдачи над экраном для PgUp/PgDn (по умолчанию `1000`; `0` — не сохранять) |
| `[terminal] undo` | глубина отмены правок набора в АВТОНОМНО, клавиша **Ctrl+U** (по умолчанию `20` — столько шагов/слов; `0` — отмена выключена) |
| `[terminal] pulse` | интервал «пробела поддержки» в линию, секунд (по умолчанию `60`): раз в это время в линию уходит пробел, чтобы программы БЭСМ-6, ждущие ввода, не считали сеанс уснувшим и не сбрасывали его; **только в АВТОНОМНО** — в С ЭВМ лишний пробел вклинивается в выдачу и сбивает её; пробел без ПР строку не заканчивает, эхо его на экран не выводится; `0` — выключить (то же — `--pulse`) |
| `[terminal] check` | интервал проверки живости линии, секунд (по умолчанию `60`): раз в это время у линии (моста SSH) спрашивается состояние; ответа нет — в подвале `ЛИНИЯ=НЕТ` (связь пропала «молча»), мост отвечает — подвал по-прежнему показывает `ЛИНИЯ=КВУ`/`ЛИНИЯ=ДКС`; `0` — выключить (то же — `--check`) |
| `[terminal] nabor` | НАБОР: `n0` — ASCII, `n1` — русские верх+низ (КОИ-7 Н1) с русской раскладкой, `n2` — VT-52 (по умолчанию); он же `--nabor`, переключается F8; устаревшие `sets`/`charset` уступают ему |
| `[terminal] layout` | русская раскладка: `positional` — по положению клавиш ЙЦУКЕН (по умолчанию: q→Й), `phonetic` — фонетическая (q→Я, w→В), `off` — выключена |
| `[terminal] koi7` | `true` — включить раскладку (`layout` по умолчанию — позиционную), если `layout` не задан |
| `[terminal] mouse` | `false`/`off` — мышь остаётся терминалу (колесо листает экран самого терминала); по умолчанию мышь отдана эмулятору: колесо листает «историю» выдачи по три ряда, циклической прокрутки нет |
| `[terminal] fit` | `true`/`on` — подгонять окно терминала ровно на «25 рядов кадра + подвал» (`CSI 8;h;w t`, сбой масштаба возвращается при приходе символа от ЭВМ); по умолчанию окно не трогается — кадр ЭВМ сам дотягивается до низа окна |
| `[terminal] help` | `true`/`on` — показать ряды-справку (легенду клавиш) при старте; по умолчанию справка **скрыта**, нижняя строка состояния остаётся в любом случае, освободившиеся ряды достаются кадру (то же — `--show-help`; убрать — `--no-help`). В ходе сеанса переключается **F12** (скрытая — подсказка «СПРАВКА=F12» в правом углу верхней строки состояния) |
| `[keys]` | переназначение клавиш: `что_пришло = что_набирать` — знак, строка, `KEY-имя` или код УП `\xNN` (Ctrl+клавиша); пустое значение гасит клавишу. Применяется до правил набора. Код нажатого УП видно в подвале (`ПОСЛ: УП NN`) — по нему и правят привязку. Если терминал понимает CSI-u (kitty, foot, wezterm, alacritty; xterm: `-modifyOtherKeys 2 -formatOtherKeys 1`; VTE — нет), эмулятор при запуске сам включает протокол, и тогда ключом служит само нажатие с модификатором — `ctrl+Б = <`, `alt+Х = …` — без дублей с обычными знаками; имя незакрытого сочетания тоже показывает подвал. Без CSI-u Alt читается как ESC-префикс и именуется так же (`alt+б`); если Ctrl+кириллица приходит обычным знаком (модификатор потерян) — подвал это и покажет, отличить клавишу нельзя, привяжите другой модификатор. В подвале (`ПОСЛ:`) видно каждое нажатие: знак с кодом (`б U+0431`), УП (`УП 1C`), имя с модификатором и итог переназначения (`ctrl+б→< U+003C`). В комплекте привязаны (именами и кодами, Ctrl и Alt) `ctrl/alt+Б=<`, `ctrl/alt+Ю=>`, `ctrl/alt+Х=[`, `ctrl/alt+Ъ=]`, `ctrl/alt+6=^` (`shift+?` даёт `|` и проходит без привязки) |

Другой файл: `./ie15 --conf /путь/ie15.conf`.

### Диалоговый режим (интерактивный сеанс)

Для живого диалога служит лаунчер `./ie15` — он, как и прямой запуск
`python3 -m ie15emu`, ведёт сеанс до `Ctrl-C` (ограничение по времени
только при явном `--seconds N`) и требует реального
терминала (xterm, putty, tmux; раскладка любая, нужен UTF-8).
Запуск **без аргументов** (в т.ч. двойным щелчком в файловом менеджере) —
диалог с сервером по умолчанию из `ie15.conf`: `ssh://test@besm6.cs.msu.ru`
(ключ `~/.ssh/besm_test`), линии `4202-4223` с автоматическим перебором;
после завершения окно ждёт Enter,
чтобы пользователь успел прочитать результат или ошибку:

```bash
./ie15                                              # по умолчанию: ssh://test@besm6.cs.msu.ru
./ie15 --line tcp://127.0.0.1:4202               # С ЭВМ: клавиши в линию, эхо от машины
./ie15 --line ssh://ie15@127.0.0.1:2222 --password ie15   # тот же диалог через SSH-мост
./ie15 --line tcp://127.0.0.1:4202 --mode local  # АВТОНОМНО: набор в буфер, F10 — SEND
./ie15 --port 4202-4223                          # перебор диапазона: занятая линия
                                                 # («Line connection busy» от ЭВМ)
                                                 # пропускается, подключаются к следующей
```

Порт (`--port` и `port` в конфиге) можно задать одним числом, списком
(`4202,4210`) или диапазоном (`4202-4223`): терминал идёт по портам по
порядку, занятые и недоступные пропускает; если свободных не осталось —
сообщает «нет свободной линии» со списком занятых/недоступных. У SSH-моста
то же: `--target 127.0.0.1:4199-4223` выбирает первую свободную линию
Э-60 на каждой сессии, так что одна команда подключения обслуживает все
23 линии сразу.

### Контроль состояния SSH-моста

Связь может пропасть «молча»: SSH-соединение не рвётся (тишина сети,
NAT, убитый где-то промежуточный хост), данных нет — а подвал по-прежнему
говорит `ЛИНИЯ=КВУ`/`ЛИНИЯ=ДКС`, и оператор не знает, что линии давно
нет. Поэтому терминал **регулярно спрашивает у линии состояние**
(`[terminal] check`, по умолчанию 60 с; то же — `--check`, `0` — выключить):

* запрос идёт вторым каналом того же SSH-соединения: мост
  (`besm6/ssh_bridge.py`) отвечает на exec-команду `status` отчётом —
  `МОСТ=ЖИВ`, `СЕССИЙ=N`, `ЛИНИЯ=<порт>:ЖИВА|МЕРТВА`;
* ответа нет (мост молчит, путь мёртв) — в подвале `ЛИНИЯ=НЕТ`, сеанс
  **не** завершается: набор и правка в АВТОНОМНО продолжаются, **ВВОД в
  С ЭВМ** даёт повторное соединение;
* мост жив, но линия за ним мертва — тоже `ЛИНИЯ=НЕТ` (мост сообщает
  про мёртвую линию);
* всё в порядке — подвал по-прежнему показывает `ЛИНИЯ=КВУ`/`ЛИНИЯ=ДКС`:
  состояние линии одно — в подвале, второго индикатора нет.

Сам мост тоже следит за собой: раз в 5 минут печатает в своём журнале
сводку (`--stat СЕК`, `0` — не печатать):

```
[мост] состояние: сессий 1; линия 4202 жива (312 с)
```

Несколько копий одновременно: сервер ДИСПАК поднят на 23 линии Э-60
(терминалы 2–24), порт линии N — `4199+N` (4202…4223), а 4199 — игровая
линия «ИГРА» (шифр 4199). Одна линия — одна копия (токовая петля не
мультилексируется). **Больше не нужно расписывать порты руками**: по
умолчанию (в `ie15.conf`, в лаунчерах `./ie15` и `ie15.cmd` и у
SSH-моста) стоит диапазон `4202-4223` — каждая следующая копия сама
проходит по занятым линиям и берёт первую свободную; если свободных нет,
терминал сообщает «нет свободной линии» со списком занятых/недоступных.
Явный выбор — `--port` (число, список или диапазон) или `--line
tcp://host:диапазон`. После преждевременного выхода копии слот Э-60
освобождает ОС, переподключение может подождать несколько секунд (тесты
переподключаются сами).

Порядок в ДИСПАК: подсказка `Type HYC<enter>` — набрать `HYC` и Enter
(эхо у линии по умолчанию выключено), дождаться «ЗДРАВСТВУЙТЕ! ОС ДИСПАК…»,
затем приказы (`ВЫД`, `ЗАД`, `ГОД`, …); приглашение «ЭВМ-3,TNNN» — на пустую
строку Enter. Служебная строка внизу показывает режим. Состояние линии —
одно и только в подвале: тип канала `ЛИНИЯ=КВУ` или `ЛИНИЯ=ДКС`
(`?` — баннер SIMH ещё не пришёл), а при обрыве связи — `ЛИНИЯ=НЕТ`. При фактическом
обрыве линии сеанс НЕ завершается: служебная строка показывает
`ЛИНИЯ=НЕТ`, набор и правка в АВТОНОМНО продолжаются, отправка в линию
подавляется; **ВВОД в С ЭВМ в этом состоянии вызывает повторное
соединение** (удача — `ЛИНИЯ: восстановлена` и новый баннер в статус,
неудача — `ЛИНИЯ: не подключилась`, ВВОД повторит попытку). Обрыв,
который сам по себе не заметен (связь пропала «молча»), ловит
регулярная проверка состояния линии (см. «Контроль состояния SSH-моста»).

### Клавиши терминала (в сеансе)

| Клавиша ПК | Действие |
|---|---|
| обычные знаки | ввод в линию (С ЭВМ) или в буфер (АВТОНОМНО) |
| Enter / Tab / Ctrl-G | ПР ПС (`0D 0A`) / ТАБ (`09`) / ЗВН (`07`); Enter в С ЭВМ при `ЛИНИЯ=НЕТ` — повторное соединение |
| Backspace | ВК (`08`, «authbs»); в АВТОНОМНО при открытом выделении стирает выделенное (см. Shift+Backspace) |
| Стрелки / Home / End | `ESC A/B/C/D`, `ESC H`, `ESC K` (набор команд №2); в АВТОНОМНО те же клавиши двигают курсор по буферу набора (в С ЭВМ — коды терминала, как на настоящем 15ИЭ) |
| PgUp / PgDn | листание «истории» выдачи и экрана вверх/вниз (до первой и последней выданной строки, без циклического показа пустоты); вверх — только когда выдано больше одной страницы кадра; в линию не уходит. Листается только текст: подвал остаётся по нижней кромке окна. **Долистали вниз — окно снова следящее**: дальше оно само идёт за выдачей (раньше закреплённое окно отставало от текста на строку, курсор уходил под нижнюю кромку и экран приходилось опускать вручную) |
| протяжка мышью (левая кнопка) | выделение текста в кадре или в истории; **строчное** — от нажатой строки до отпущенной. Направление протяжки не важно: в пределах одной строки выделяется тот же диапазон знаков, что и при обратном движении. С **Ctrl** — **колонкой**: прямоугольник знаков, одинаковый для всех рядов (как в xterm); фрагментов может быть несколько, каждый показан инверсией (в том числе уже во время протягивания). Начало протяжки держится за строку, а не за ряд окна: если во время протяжки ЭВМ печатает, выделение идёт по ходу выдачи — от нажатой строки до отпущенной (как в обычных терминалах); отпускание над подвалом заканчивает выделение по последней строке с текстом; строки с одинаковым текстом подсвечиваются по отдельности. Размер и вид выделения видны в строке состояния: `ВЫД=СТР 1фр 1с 15зн` или `ВЫД=КОЛ 1фр 4с 12зн` |
| **Ctrl+U** | **ОТМЕНА** правки набора в АВТОНОМНО — **по слову**: буфер возвращается на шаг назад, а шаг — это слово целиком (пробел/точка/ПР закрывают шаг, как и дискретные правки), а не одна буква. Движения курсора (стрелки, Home/End, листание) шаг не закрывают — набор до и после навигации откатывается одним шагом. Глубина — `[terminal] undo`, по умолчанию 20 слов/действий; `0` — выключить. Отменяется всё, что меняло буфер: набор, **ВЗЯТЬ** (F4), удалённая F5 страница. На экране прежнее эхо стирается, остаётся ровно то, что в буфере; сколько шагов ещё доступно — видно в строке состояния (`ОТМЕНА=Ctrl+U (7)`). ПЕРЕДАЧА (F10) отдаёт буфер — историю отмены сбрасывает: отданное в линию отменять нечего. В режиме С ЭВМ своего буфера нет, отменять нечего |
| **Ctrl+L** | **УДЕРЖАНИЕ** экрана (только С ЭВМ) — выдача ЭВМ останавливается: эмулятор перестаёт читать линию, выдача копится в буфере сокета и **машина упирается в него** (защита от зациклившихся программ, «заливающих» экран), а экран замирает на том, что на нём. Одновременно в линию уходит команда 15ИЭ **«Сброс» (0x0C)**: на линии, объявленной ОС терминалом «Э» (приказ `НУС <N> 1` — «ТИП ТЕРМ: 1 → ЭЛЕКТРОНИКА»), ДИСПАК трактует её как DEL/ERASE и **отменяет идущую выдачу** (ОТМЕНА ВЫДАЧИ, признак BREAK); на линиях типа «T» (Видеотон) код до ОС доходит, но игнорируется — там поток останавливает сам эмулятор. Эхо «Сброса» срезается: в кадре 0x0C отработал бы как «ДОМ» и увёл бы курсор в начало. Повторное нажатие — снять удержание. Признак — в подвале `УДЕРЖ=ВКЛ` (в С ЭВМ на его месте «БУФЕР=» — он там всегда пуст) и в строке состояния |
| **Ctrl+Q** | **К ВЫДАЧЕ** — снять удержание, а если его не было — вернуть окно к живой выдаче (следящий режим). Соответствует команде 15ИЭ «Восстановить передачу» (0x11); ДИСПАК этот код для 15ИЭ игнорирует, поэтому в линию он не уходит |
| **F3** / **F4** | **СБРОС** — снять всё выделение; **ВЗЯТЬ** — отдать выделенный текст в буфер набора (АВТОНОМНО) или сразу в линию (С ЭВМ), после чего выделение снимается; ПЕРЕДАЧА (F10) отдаёт накопленное |
| колесо мыши | листание «истории» по три ряда за щелчок (мышь терминала отдана эмулятору, `mouse = off` в конфиге — возвращает её терминалу); вверх — как PgUp, без циклической прокрутки; подвал не уезжает |
| Shift+стрелки | **выделение построчное**: первая клавиша открывает протяжку от курсора 15ИЭ (вбок — знак под курсором, вверх/вниз — остаток строки от курсора), следующие тянут её конец; фрагмент фиксирует любая другая клавиша (или **F4**, которая выделенное забирает). Подсветка и счёт «ВЫД=СТР …» — как у мыши |
| Shift+Ctrl+стрелки | то же **поколонное**: прямоугольник знаков, одинаковый для всех рядов |
| **Ctrl+Home** / **Ctrl+End** | **выделение части строки набора**: от курсора до начала / до конца строки (АВТОНОМНО — по буферу, С ЭВМ — по кадру, как Shift+стрелки); удаляется Shift+Backspace, берётся F4. Формы `ESC [ 1 ; 5 H/F` и `ESC [ 1 ; 5 ~` / `ESC [ 4 ; 5 ~` |
| Shift+Home / Shift+End | **заблокированы**: ОС перехватывает их на листание вывода и в приложение они не доходят, а где доходят — эмулятор их гасит, чтобы поведение не зависело от терминала (формы `ESC [ 1 ; 2 H/F`, `ESC [ 1 ; 2 ~`); выделение строки — за Ctrl+Home/End |
| **Shift+Backspace** | **удалить выделенное** (набор, АВТОНОМНО); выделения нет — работает обычный ВК. Обычный **Backspace при открытом выделении тоже удаляет выделенное** (как в редакторе) — это спасает терминалы вроде xterm, где Shift+ВК и обычный ВК неразличимы и шлют один `\x7f`. В С ЭВМ гасится: кадр принадлежит ЭВМ |
| Alt+стрелки и прочие стрелки с модификаторами | на клавиатуре 15ИЭ таких нет — гасятся целиком, в линию не идут (иначе escape-мусор «ESC [ 1 ; 3 A» уходил бы в ЭВМ и забивал кадр) |
| Ins / Del | `ESC b` / `ESC c` (инверсное / нормальное видео) |
| Ctrl+← / Ctrl+→ | курсор на начало текущего / следующего слова (разделители — пробел и точка) |
| Ctrl+↑ / Ctrl+↓ | курсор в начало текущей / нижней строки |
| **F5** | **ОЧИСТКА** — удаляет то, что сейчас на кадре. В **АВТОНОМНО** из буфера уходит видимая страница набора (строки, которые кадр показывает сейчас; повторное F5 снимает следующую страницу, пока буфер не опустеет; Ctrl+U возвращает). Если на кадр загружена страница «истории» (PgUp) — F5 удаляет её из истории. В **С ЭВМ** прежнее поведение: экран уходит в «историю», история не стирается |
| **F6** | **ЭХО** — подавить вывод набора на экран (для паролей): клавиши уходят в линию, но не печатаются; эхо-ответ линии срезается до повторного нажатия |
| **F7** | **УПР.СИМВ** — показывать/скрывать образные знаки управляющих символов (режим blink ВТ-340); по умолчанию выключен |
| **F8** | **НАБОР** — Н0 ↔ Н1 ↔ Н2 (VT52) |
| **F9** | **СЕТЬ** — АВТОНОМНО ↔ С ЭВМ. При переходе в АВТОНОМНО текст кадра добавляется в буфер набора (перенос отменяется Ctrl+U; буфер можно очистить F3) — набор продолжается ниже текста экрана, строки ЭВМ не пропадают и при наборе буфера больше экрана |
| **F10** | **ПЕРЕДАЧА (SEND)** — отдать буфер в линию, очистить его и перейти в С ЭВМ |
| **F12** | **СПРАВКА** — показать/убрать ряды-легенды подвала прямо в сеансе; состояния и `ПОСЛ:` остаются всегда, скрытая справка сама подсказывает — «СПРАВКА=F12» прижата к правому краю верхней строки состояния. При старте справка скрыта (`--show-help`, `[terminal] help = on` — показать сразу). Формы F1 (`ESC [ 11 ~`, `ESC O P`, `ESC [ [ A`) тоже распознаются |
| Ctrl-C | выход |

(F11 не используется — занят окружением рабочего стола; F1 в ряде окружений занят ОС — потому основная клавиша справки F12)

**Диагностика клавиш.** Если комбинация не работает — запустите с журналом
`python3 -m ie15emu --keylog /tmp/keys.log`: в файл пишется каждая порция
ввода (сырые байты, недобранный хвост escape-последовательности, результат
разбора) и чем закончился сеанс. Если терминал вообще не шлёт байты —
снимите их независимо от эмулятора: `python3 tools/showkeys.py` (печатает
hex/repr каждого нажатия и разбор `decode_keys`), чтобы понять, шлёт ли
терминал нужную форму.

#### Н2: раскладка не нужна, регистр ввода не важен

В Н2 терминаль одно-регистрный (так же отвечает ЭВМ): русская строка
на линии — коды ЭВМ без деления на регистр, поэтому реальную раскладку
клавиатуры переключать не нужно, а регистр ввода на результат не
влияет (`Ц` и Shift+`Ц` — один код ЭВМ; сами заглавные даёт клавиатура
15ВВВ). Для латиницы Shift (или CapsLock) продолжает выбирать алфавит:

| Что нажато | Латинская раскладка ОС | Русская раскладка ОС |
|---|---|---|
| буква без Shift/Caps | английские заглавные | русские заглавные |
| буква с Shift (или любой буквой включённый **CapsLock**) | русская буква того же положения ЙЦУКЕН (W→Ц) | та же русская буква — регистр в Н2 не важен |

Знаки `^ @ # № [ ] ' | ? % ; ! > <` набираются одним и тем же знаком с
обеих раскладок и при любом положении CapsLock (карта построена по
самому знаку): на латинской раскладке — обычные клавиши (№ — AltGr),
на русской — общая физическая клавиша: `"` (Shift+2)→`@`, `:` (Shift+6)
→`^`, `№` (клавиша 3)→номерной знак `№` (на линию — позиция 2/3),
`ё/Ё` (клавиша `|`)→`|`, `ъ/Ъ` (клавиша `]`)→`]`; `'` и `[` —
Shift+`э`/Shift+`х` (те же клавиши, где на латинской раскладке `'` и
`[`); `# ? % ; !` на русской раскладке — те же Shift+3/7/5/4/1, что и
на латинской. `«`/`»` и неразмеченные клавиши в Н2 не переводятся; чего
не хватает на русской раскладке (`<`, `>`) — добирается Ctrl-сочетаниями,
привязанными в секции `[keys]` конфига.

### Жёсткий терминал

Эмулятор рисует кириллицу (текст ЭВМ и подвал) и псевдографику (блок
заливки, «№», стрелки легенды). Обычный терминал это показывает, а
**«жёсткий»** — нет: при `LC_ALL=POSIX` кодировка вывода `ascii`, и первый
же русский знак обрывает сеанс `UnicodeEncodeError`.

Поэтому вывод идёт через `ie15emu/hardterm.py`: кодировка терминала
определяется по локали, и если она не берёт кириллицу с псевдографикой,
включается подстраховка. Знак, который кодировка не берёт, заменяется на
ближайший печатный — решение принимается **по одному знаку**, а не целиком:

| Кодировка терминала | Что происходит |
|---|---|
| `utf-8` | ничего не трогаем — обычный режим |
| `koi8-r`, `cp866` | кириллица и псевдографика остаются (это их родные знаки); заменяются только «№» и стрелки |
| `ascii`, `latin-1` | кириллица → латиница (транслитерация), псевдографика → ASCII (`█`→`#`, `─`→`-`, `│`→`|`), стрелки → `^ v > <` |

Например, `ПРОВЕРЬ ЛИНИЮ!` на ASCII-терминале показывается как
`PROVER' LINIYu!` — работать можно, пусть и в транслитерации. Управляющие
последовательности (позиционирование, цвет) всегда ASCII и подстраховкой не
затрагиваются. Решение кэшируется по знаку, так что после первого кадра
перебор кодировок не повторяется.

Ничего настраивать не нужно: подстраховка включается сама. Если терминал
юникодный, но локаль не выставлена (`LANG` пуста), вывод будет
транслитерирован — задайте `LANG=C.UTF-8` (или `ru_RU.UTF-8`), и пойдёт
настоящая кириллица.

#### Консоль Linux: клавиши F1–F5

Терминал Linux-консоли (TERM=linux) шлёт функциональные клавиши F1–F5
старым форматом `ESC[[A`…`ESC[[E` (а не `ESC[11~`…`ESC[15~`, как xterm).
Эмулятор понимает обе формы для занятых клавиш: **F1** — справка подвала,
**F3** — снять выделение, **F4** — взять в буфер, **F5** — ОЧИСТКА;
остальная F2 консоли в линию не уходит (ESC гасится, дальше идут
печатные знаки). На самой консоли F1 может перехватывать ОС (переключение
виртуальной консоли) — тогда справку переключает F12 (xterm-форма `ESC[24~`).

#### Консоль Linux (Ctrl+Alt+F1…F6) — шрифт, а не кодировка

На виртуальных консолях (`tty1`…`tty6`) русские буквы часто **не видны**,
хотя программа выводит их совершенно правильно. Причина не в эмуляторе и
не в локали: консоль по умолчанию рисует **встроенным шрифтом ядра
VGA 8×16, в котором нет кириллических глифов**. Байты приходят, а рисовать
нечем. Лечится шрифтом, и это делает установщик — из коробки:

```sh
./install.sh                 # спросит sudo
./install.sh --no-vconsole   # оставить консоли как есть
```

Он кладёт в `/etc/vconsole.conf` подходящий `FONT=` и перезапускает
`systemd-vconsole-setup`, чтобы шрифт применился ко всем консолям.

Но настраивать консоли можно и **отдельно от установки** — например, когда
терминал уже поставлен, а шрифт поменяли руками:

```sh
sudo ./fix-console.sh
```

Это тот же скрипт, который вызывает `install.sh`; он сам поднимет права до
root (перезапустит себя через `sudo`), если запущен не от root.

**Универсального имени шрифта не существует.** На машине без пакета `kbd`
лежит только встроенный VGA-шрифт ядра — а в нём кириллицы нет; какие
именно файлы приедут, зависит от дистрибутива. Поэтому установщик не
зашивает одно имя, а перебирает список известных и берёт **первый, который
реально лежит на диске**:

```
cyr-sun16 → Cyr_a8x16 → Cyr_a8x14 → Cyr_a8x8 → koi8r.8x8
          → LatArCyrHeb-16 → LatArCyrHeb-08
          → LatGrkCyr-8x16 → pancyrillic.f16
```

Порядок не случаен: `cyr-sun16`, `Cyr_a8x*` и `koi8r.8x8`, кроме кириллицы
и псевдографики, содержат **глифы стрелок** `↑ ↓ → ←` — подвал
(`ЭКРАН↑=PgUp`, `СЛОВО=Ctrl+→`) рисуется как задумано. У `LatArCyrHeb-*`
стрелок нет (заменяются на `^ v > <` — читать можно, но похуже), поэтому
эти шрифты стоят в списке после них.

Берутся только `.psfu` — такой шрифт несёт **встроенную карту юникода**, и
консоль в режиме UTF-8 знает, какой глиф на каждую букву. Обычный `.psf`
(например популярный `UniCyr_8x16`) карты не несёт, и на UTF-8-консоли
русские буквы в нём опять схлопываются в один глиф — поэтому такой шрифт
установщик не выбирает, а прямо говорит, что делать вручную
(`setfont UniCyr_8x16 -u koi8-r`).

Если не нашлось ничего — установщик не молчит, а выдаёт готовую команду
установки (`sudo apt install kbd`, либо `console-setup` на
Debian/Ubuntu) и объясняет, что без шрифта русские буквы не появятся.

### Мышь на консолях

`fix-console.sh` настраивает ещё и **мышь**: без неё выделение текста мышью
на консоли не работает.

Дело в том, что **виртуальная консоль ядра события мыши терминалу сама не
отдаёт** — их перехватывает демон `gpm` и превращает в escape-последовательности
(X10, `ESC [ M` + три байта). Эмулятор такие читает: протяжка выделяет текст,
колесо листает «историю» выдачи. Без `gpm` мыши на консоли просто нет.

Скрипт находит устройство (`/dev/input/mice`, иначе — мышиный узел
`/dev/input/by-id/…`, клавиатуры пропускает), записывает его в `device=`
в `/etc/gpm.conf` (прежние настройки и бэкап сохраняются) и включает службу:

```sh
sudo apt install gpm      # если gpm ещё нет
sudo ./fix-console.sh     # найдёт мышь и включит её
```

Второй способ — параметр ядра `mouse=1` в командной строке загрузки, но он
требует перезагрузки и неудобен: проще `gpm`.

Проверка: запустите терминал на консоли (мышь включена по умолчанию,
`--mouse`) и протяните по тексту — он подсветится инверсией, `F4` заберёт
выделенное в буфер набора, `F3` снимет его.

**Не смешивайте режимы.** У консоли ядра два несовместимых варианта:

| Режим | Раскладка | Локаль | Нужен шрифт |
|---|---|---|---|
| UTF-8 | `KEYMAP=…-UTF-8` | `ru_RU.UTF-8` | юникодный `.psfu` (`LatArCyrHeb-16`) |
| Кодовая страница | `KEYMAP=…-KOI8-R` | `ru_RU.koi8r` | кодировочный (`koi8r-8x16`) |

Взять шрифт от одного режима, а локаль и раскладку от другого — значит
получить мусор вместо букв: консоль в UTF-8-режиме разберёт КОИ8-R байты
как невалидный UTF-8, и **все кириллические знаки схлопнутся в один глиф**
(все буквы подвала станут «Ч»). Ошибка видна и на самой консоли, и в дампе
буфера — `sudo cat /dev/vcsN | od -c`: вместо разных байт подряд идёт один
и тот же.

Установщик держит **UTF-8** (так уже настроены X11 и оконные терминалы) и
меняет только шрифт — это минимальное вмешательство. Если раскладка была
переведена в `-KOI8-R`, он вернёт `-UTF-8` и уберёт drop-in с локалью
`ru_RU.koi8r`.

Посмотреть, что реально нарисовано на консоли (нужен root — `/dev/vcsN`
доступен группе `tty`):

```sh
sudo cat /dev/vcs3 > /tmp/tty3.bin
stty size < /dev/tty3 > /tmp/tty3_size.txt
python3 tools/show_console.py /tmp/tty3.bin /tmp/tty3_size.txt utf-8
```

Если байты не читаются (сплошные `FE` на месте кириллицы) — консоль
находится в смешанном режиме: раскладка однобайтовая, а шрифт юникодный
(см. таблицу выше). Это и есть та самая ошибка, когда все буквы видны
как один «Ч».

### Кодировка КОИ7 Н1

Русские буквы кодируются по 7-разрядной таблице (ГОСТ 27463-87):

| Диапазон кодов | Содержимое |
|---|---|
| `0x00…0x1E` | заглавные русские (Н1): Ю А Б Ц Д Е Ф Г Х И Й К Л М Н О П Я Р С Т У Ж В Ь Ы З Ш Э Щ Ч |
| `0x20…0x5F` | цифры, знаки, заглавные латинские |
| `0x60…0x7E` | строчные русские (тот же порядок, код `\| 0x60`) / `0xE0…0xFE` — они же с битом алфавита |
| `0x7F` | сплошная заливка (непрозрачный блок) |

Заглавные Н1 (`0x00…0x1E`) сталкиваются с управляющими кодами («М»=`0x0D`
= ПР), поэтому во внутреннем потоке (парсер, буфер SEND) русские буквы
несут **бит алфавита** 0x80: заглавная = `0x80…0x9E`, строчная = `0xE0…0xFE`.
В ОЗУ кадра после `put()` остаётся 7-разрядный код ВЗУ.

Линии SIMH БЭСМ-6 говорят в трёх кодировках; режим ПЕРЕДАЧИ выбирается по
баннеру при подключении (`Encoding is …`), приём определяется по самому
потоку (`ie15emu/charset.py`):

| Линия (команда SIMH) | ЭВМ → терминал | терминал → ЭВМ |
|---|---|---|
| `set ttyN unicode` (по умолчанию) | UTF-8 | UTF-8 (`unicode_to_koi7` в SIMH кладёт букву в строку `0x60…`) |
| `set ttyN raw` / `raw8` | внутренние коды БЭСМ-6 | те же коды: буква — строка `0x60…0x7E`, конец строки — ETX |
| `set ttyN jcuken` / `qwerty` | UTF-8 | та же строка `0x60…0x7E` (живой эталон: «ВЫД» → `wyd`) |
| `set ttyN dks,raw` (линия Э-60) | внутренние коды БЭСМ-6 (НУСов нет; подтверждение ОС — «NNNN) ») | те же коды, окончание строки — ПР (Э-60 читает ПР/ПС, не ETX) |

Функции тракта: `encode_koi7()` (Unicode → КОИ7 с битом алфавита),
`decode_koi7()` (ОЗУ кадра → Unicode), `normalize_line_bytes()` /
`normalize_incremental()` (поток ЭВМ → парсер, с дозаполнением разорванного
UTF-8), `to_line()` (внутренний поток → байты линии). Telnet-IAC вырезается
stateful в `link.py` (`IacStripper`), ESC Z получает ответ `ESC /` в линию.
Поэтому обмен с БЭСМ-6 идёт русскими буквами в обе стороны без искажений.

## Программное управление (агент ИИ)

Эмулятором можно управлять из программы: `ie15emu.agent.Terminal` —
подключение к линии, чтение кадра текстом, ожидание конца выдачи, набор
клавишами. Пример — `tools/agent_igra.py` (агент играет на БЭСМ-6).

```
tmux send-keys -t besm6 'П' 'О' 'В' Enter     # приказ ОС — оператору (tty1)
python3 -m ie15emu --line tcp://127.0.0.1:4202 --dump - --status
```

**Правило нулевого шага:** при любой диагностике неисправности и перед
выполнением приказа ОС сначала читаются справочники — «Руководство
оператора» ОС ДИСПАК
(`../re_dispak/re-dispak/docs/Dispak-operator-guide.md`,
разделы 4.x — директивы, 5.x — сообщения), протокол линии ДКС
(`../simh/BESM6/doc/ДКС.md`), справочники модулей
(`../re_dispak/re-dispak/ai/`) и
[`DISPAK_AGENT.md`](../re_dispak/re-dispak/docs/DISPAK_AGENT.md).
Приказ может выполнить не то, а сообщение может значить не то, что кажется
по его тексту.
