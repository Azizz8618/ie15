# ДИСПАК и СЕРП: работа с машиной из агента

Справочник для программы, которая ходит в ОС ДИСПАК через эмулятор
терминала 15ИЭ (`ie15emu.agent`). Все сведения — из текстов ОС проекта
`re_dispak` (исходники `*.be`, справочники `ai/`) и протокола линии ДКС
(`simh/BESM6/doc/ДКС.md`); ссылки `файл:строка` — по исходникам.

## 0. Правило нулевого шага: сначала справочники

**Как только появилась диагностика неисправности или понадобилось выполнить
приказ ОС ДИСПАК — сначала читаем справочники, и только потом пробуем на
машине.** Свои догадки и «проверим, сработает ли» здесь не работают: приказ
может выполнить не то (например `СБО` без параметров **исключает все
устройства вывода из конфигурации системы** — см. 4.5.4), а диагностика
может означать совсем не то, что кажется по её тексту.

| Что нужно | Где искать |
|---|---|
| что означает сообщение ОС, что делать оператору | `re-dispak/docs/Dispak-operator-guide.md` — «Руководство оператора», разделы 5.x (сообщения) и 4.x (директивы) |
| как устроены линия ДКС, кольца, буферы | `simh/BESM6/doc/ДКС.md` |
| устройства, связь, буферы, приказы — по модулям | `re_dispak/re-dispak/ai/` (СВЯЗЬ7, МОТТ, БОНБОТ, ДИСП70, ВЗУ, ТЕРМ) |
| устройство приказа в коде | `re_dispak/bonbot.be` (таблица `ДЕШ`, права `МРДИРО`/`ШКОПТТ`), `prik*.be` |
| запуск задач по шифру, ответы `Ф…` | `re_dispak/puschach.be` |
| этот файл | `docs/DISPAK_AGENT.md` |

Правило применяется и к агенту (`ie15emu.agent`): незнакомый приказ или
непонятное сообщение — сначала `re-dispak/docs/Dispak-operator-guide.md`
и `ai/`, потом эксперимент на живой машине.

## 1. Линия: два типа, разный вход

| Тип | Признак | Вход |
|---|---|---|
| **ДКС** (Э-60 через концентратор) | баннер `Connected to DKS` | **НУС не нужен**: пустая строка (`Enter`) — и ОС здоровается `ЭВМ-N,Т0NN` |
| **КВУ** (токовая петля, serial) | баннер `Encoding is RAW`, без `Connected to DKS` | вход командой `НУС` (`prik6.be:72-83`), затем пустая строка |

Это видно и в живом опыте: на линии 4205 (ДКС) достаточно нажать Enter —
через несколько секунд приходит `ЭBM-3,T020`. Первый ввод после входа
машина иногда «съедает» — приказ/команду при `ОШИБ` надо повторить.

**Шрифты.** На линии приходит КОИ-7. В наборе Н2 русские буквы машины
выводятся латинскими гомоглифами: `ВАШ ХОД` → `BAШ XОД`, `ИГРА` →
`ИГPA`. **Сравнивать выдачу с образцом надо через `ie15emu.agent.fold()`**,
иначе поиск по экрану ничего не находит.

**Набор при вводе.** В Н2 строчная латинская буква даёт верх
международной строки, а строчная кириллица — коды ЭВМ. Поэтому команды
ОС набираются **строчными** русскими буквами (`t.type("игра 412201")`),
а `НУС` — строчными латинскими (`t.type("hyc")`).

## 2. Права терминала: приказы только с операторского

Приказ (директива) — трёхбуквенная мнемоника из таблицы `ДЕШ`
(`bonbot.be:1835-1939`). Разбирает их модуль ПРИКАЗ (`prikaz.be`), и перед
выполнением ОС проверяет права (`bonbot.be:1252-1261`):

```
СМОТР СЧ ШКОПТТ
 И Е48(М2)
 ПЕ НАША         С ТЕРМ.ОПЕР.МОЖНО ИСП.ЛЮБУЮ ДИР-ВУ
 ... сч МРДИРО / и Е48(М12) / пе НАША
ДЗАПРЩ уиа ТЗАПР-БОНБОТ(М16) / пб ВЫДАЧ
```

* **Операторский терминал** (в шкале `ШКОПТТ`) — может любой приказ.
* **Обычная линия ДКС** — только то, что разрешено маской `МРДИРО`
  (`bonbot.be:1975`, `0o4440106500060140`); на остальное ОС отвечает
  **«ВАМ НЕЛЬЗЯ»**.
* Стать операторским терминал может только по команде оператора с его
  операторского терминала: **НУС `<N>` 1** («ТИП ТЕРМ: 1 → ЭЛЕКТРОНИКА»,
  `prik6.be:72-83`), либо **ПУЛ** (`prik6.be:16-18`).

Проверено вживую: с обычной линии ДКС `СБОЙ 1` → `ВАМ НЕЛЬЗЯ`, `ВЦП` →
`ЗНЕТ`/`НЕТ` (ответ, но не всегда разрешён).

В коде: `Terminal.probe_operator()` (пробует приказ, которого нет в маске —
`сбой`), `Terminal.set_operator(True)` после того, как оператор сделал НУС,
`is_directive()` — отличить приказ от запуска задачи. `run_task()` приказ
не пропустит.

**Итог для агента:** задачи запускаются своим шифром (раздел 3), приказы
ОС — только по договорённости с оператором и с его терминала.

## 3. Задачи: запуск по шифру, свои шифры агента

Задачу запускают **именем и шифром**, не приказом: `ИГРА 4199`. Пускач
ищет шифр в каталоге (`puskach.be:157-175`), старшие разряды задают
раздел/ЭВМ, младшие три — номер каталога (`puskach.be:538-576`).

Ответы — `Ф` + код (`puskach.be:452 ТФОРМ «Ф»`):

| Код | Смысл (`puskach.be`) |
|---|---|
| `Ф001` | `НВВЕ` — задача в решении |
| `Ф002` | шифр/подчинённая задача не совпала |
| `Ф004` | `НКЛЮ` — ключ не найден в каталоге |
| `Ф005` | `ПЛАН` — закрыто по расписанию |
| `Ф10000` | нет связи с графиопостроителем |

**Свои шифры агента.** Диапазон **4122xx** (`AGENT_CIPHER_BASE = 412200`,
`agent_cipher(n)` → `412201`, `412202`, …). Тогда в списке задач (приказ
`НОМ`), в журнале ОС и на экране сразу видно, где работает агент:
`ИГРА 412203` — наша, `ИГРА 4199` — человеческая. Запуск:

```python
from ie15emu.agent import Terminal, agent_cipher
with Terminal("tcp://127.0.0.1:4202-4223") as t:
    t.drain()                      # забрать всё, что машина уже выдала
    t.key("KEY_ENTER")             # ДКС: приглашение ОС
    t.wait_quiet()
    print(t.run_task("игра", agent_cipher(1)))     # → хвост с ответом ОС
```

`run_task()` сам повторяет команду, если машина «съела» первый ввод
(`ОШИБ`).

## 4. Ответы ОС: что значит

| Ответ | Значение | Источник |
|---|---|---|
| `ОШИБ` | приказ не найден в таблице | `prikaz.be:909` |
| `ВАМ НЕЛЬЗЯ` | приказ запрещён маской `МРДИРО` | `bonbot.be:1989` |
| `НЕТ` | нет задачи / нет диалект. задачи | `prikaz.be:907` |
| `ЗНЕТ` | задача занята | `prikaz.be:908` |
| `К РАБ` | приказ уже выполняется | `prikaz.be:915` |
| `ЕСТЬ` | успех | `prikaz.be:906` |
| `ТЕРМ.ОТКЛЮЧ` | терминал под маской заказа `МСЗАК` | `bonbot.be:2000` |
| `НАБЕРИТЕ «ДА» ИЛИ «НЕТ» !` | игра/программа ждёт ответа да/нет | программа ИГРА |
| `ПЕРЕП. БУФЕРА ВЫВОДА` | см. раздел 6 | `plan.be:444` |

Прервать работающую программу и вернуться к ОС можно **символом 207**
(СТРЛО — сброс линии терминала, `mott.be:606-607, 710-714`) либо приказом
**ОСТ** (останов задачи, `bonbot.be:1649`). В агентском слое — символ
`\x87` в Н2 или приказ ОСТ (нужны права оператора).

## 5. Правила работы с линией (иначе будет «ПЕРЕП. БУФЕРА ВЫВОДА»)

1. **Читать линию всегда.** На каждый терминал у машины свой буфер вывода
   (СВЯЗЬ7, `М16 — АДРЕС БУФЕРА S-ТЕРМИНАЛА`, `svyaz7.be:20-23`;
   длина буфера обмена с ДКС — `1171₈` слов, `svyaz7.be:1489`). Терминал,
   который читает «между командами», переполняет буфер.
2. **Дренировать перед набором.** `Terminal.drain()` = `wait_quiet()`:
   забрать всё, что машина уже выдала, и дождаться тишины.
3. **Закрываться дочисто.** `Terminal.close()` добирает хвост выдачи
   перед разрывом; обрыв с недобранным выводом оставляет буфер полным.
4. **Не частить переподключениями.** СВЯЗЬ7 берёт буфер через ТБУФ
   («ДАЙ ИЛИ ВОЗЬМИ БУФЕР», `disp70.be:2375-2384`), и при частых обрывах
   состояние «плохой буфер» залипает.
5. **Не путать линии.** Порт линии N = `4199+N` (4202…4223); 4199 — игровая
   линия «ИГРА» (шифр 4199). Слот занят — TCPLink берёт следующую свободную.

Всё это в `ie15emu.agent`: фоновый поток чтения линии (`read_async=True`),
`drain()`, `wait_quiet()`, дочистка в `close()`.

## 6. «ПЕРЕП. БУФЕРА ВЫВОДА» — что это на самом деле

Сообщение печатает ПЛАН (`plan2.be:56-74`), текст — `plan.be:443-445`:

```
********** ПРОВЕРКА ПЕРЕПОЛНЕНИЯ БУФЕРА ВЫВОДА **********
 ОТПР / СЧ РЯПСЗ / И Е12 / ПО ХОРБУФ   НЕТ ПЕРЕП.БУФЕРА
 ...
ПЛОХБ1 ВЧОБ ВРЕМЯ / ВЧАБ Е17 21 МИНУТА
 ПЕ ХОРБУФ   ПОВТОРЯТЬ ВЫДАЧИ РАНО
```

* Флаг ставит **РОБОТ (АЦПУ)**: `НЕТМЕС СЧ РЯПСЗ / ИЛИ Е12 / ЗП РЯПСЗ`
  (`robot.be:887-890`), при нехватке зон вывода `ЗОНВЫ`
  (`disp70.be:857`, `robot.be:823 В БУФ ВВОДА-ВЫВОДА МНОГО МЕСТА`).
* Сбрасывается сам при освобождении зон (`robot.be:1556-1559`,
  `robot.be:500-503`) — отдельного приказа «сбросить» в текстах нет.
* ПЛАН после обнаружения повторяет выдачу 21 минуту, потом замолкает.

**Это не буфер терминала** (у терминала свой механизм — «БУФ. ПЕРЕПОЛНЕН»,
`svyaz7.be:835`), а исчерпание зон вывода **АЦПУ**.

**Что предписывает «Руководство оператора»** (раздел 5.40, «ОСВОБОДИ БУФЕР
ВЫВОДА»): «В процессе работы программа-планировщик систематически проверяет
степень загруженности буфера вывода… **Действия оператора: включить в
работу соответствующие устройства вывода**». Директивы — раздел 4.5
того же руководства:

| Директива | Что делает | Ответ |
|---|---|---|
| `ПОВ [<ИДЕНТ.УСТ-ВА>][<N УСТ-ВА>]` | продолжить вывод после сбоя; вывод идёт с начала зоны, на которой устройство оказалось не готово; без параметров — по всем устройствам с зафиксированным сбоем | `ЕСТЬ` |
| `ДАЙ <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]` | **подключить** устройство к конфигурации системы (`А` — АЦПУ, 0…1) | `ЕСТЬ` |
| `НЕТ <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]` | отключить устройство от конфигурации | `ЕСТЬ` |
| `СБО [<ИДЕНТ.УСТ-ВА>][<N УСТ-ВА>]` | перевести выдачу на запасное устройство; **без параметров исключает все устройства вывода из конфигурации** — обратно только через `ДАЙ` | `ЕСТЬ` |
| `СБВ` | отказ от не полностью введённой информации на буфер ввода | `ЕСТЬ` |

Порядок оператора при переполнении: `ПОВ` → если «НЕТ СБОЯ», значит сбоя
не было, а устройства просто не в конфигурации → `ДАЙ А0`, `ДАЙ А1`.
**`СБО` без параметров применять нельзя** — он сам выводит систему из
строя (убирает все устройства вывода).

Приказы 4.5 помечены `/О/` — операторские, идти с операторского терминала
(раздел 2). Признак сбоя АЦПУ — сообщение `СБОЙ А<N УСТ-ВА>`
(«Руководство оператора», 5.x): инициация — директивой `ПОВ А<N УСТ-ВА>`.

Наблюдение на живой машине (журнал ОС `log.txt`): при каждом подключении
идёт бесконечная строка

```
physobm @12542, zone = 0546, WORD = 13410030773105176
ПЕРЕП. БУФЕРА ВЫВОДА
```

— РОБОТ крутится на одной и той же зоне и не может её освободить; ОС
перестаёт выдавать часы и программы не выдают результат (частично
отвечает: `НОМ` работает).

## 7. Сценарии

```python
from ie15emu.agent import Terminal, agent_cipher, fold
```

| Сценарий | Как |
|---|---|
| Войти на ДКС | `t = Terminal(...); t.drain(); t.key("KEY_ENTER"); t.wait_quiet()` |
| Проверить права | `t.probe_operator()` → False на обычной линии |
| Запустить задачу агента | `t.run_task("игра", agent_cipher(1))` |
| Дождаться слова | `t.wait_for("ВАШ ХОД")` (сверка через `fold`) |
| Прервать программу | отправить символ 207 (`\x87`) — вернёт приглашение ОС |
| Снять выделение/взять текст | F3 / F4 терминала (`SELCLEAR` / `SELTAKE`) |
| Приказ ОС | **только с операторского терминала**; сначала прочитать руководство оператора (раздел 0) |
| Диагностика прибора | `ПОВ` → при «НЕТ СБОЯ» → `ДАЙ А0` / `ДАЙ А1` (раздел 6) |

### Операторский терминал на этой машине

В `simh/BESM6/OSZAGR/dispak.ini:129-134` операторская консоль — это
**tty1, подключённая к консоли SIMH** (`attach tty1 console`,
`set tty1 unicode,authbs`), то есть окно `besm6` в tmux. Приказы `/О/`
посылаются туда:

```bash
tmux send-keys -t besm6 'П' 'О' 'В' Enter
```

Линии ДКС — tty2…tty24 на портах 4199 и 4202…4223 (`dispak.ini:71-127`);
tty1 в сеть не выведен, и оператором с линии ДКС стать нельзя.
